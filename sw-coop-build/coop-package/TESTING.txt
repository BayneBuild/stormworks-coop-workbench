======================================================================
  TWO-MACHINE TEST CHECKLIST  -  Coop Workbench  v0.5.0-alpha  EXPERIMENTAL
======================================================================

A two-machine session is the scarcest thing this project has. A lot is built
and waiting on one, so this list is ORDERED so nothing invalidates anything
later. Please work down it in order.

----------------------------------------------------------------------
READ THIS FIRST - four rules, each of which silently voids a test
----------------------------------------------------------------------
 1. DO TEST 3 BEFORE EITHER PLAYER PLACES ANYTHING. It only exercises the code
    path being tested while neither side has placed a block yet. One local
    placement changes that path for the whole session, and it cannot be redone
    without restarting the game.

 2. MOVE THE CRAFT BEFORE TESTING THE F7 POSITION (test 8). Last time both
    machines had a zero offset, so there was nothing to carry and the test
    proved nothing. Slide the craft to a DIFFERENT spot on each machine first.

 3. DO NOT PRESS F4, F5 OR NUMPAD-* AT ANY POINT. Each reloads the whole craft.
    They are developer paths, not co-op ones, and they will confuse every
    result after them.

 4. BOTH MACHINES MUST BE ON THE SAME BUILD. Press F6 and compare the version
    AND the build stamp (e.g. "v0.5.0-alpha b0117"). Two builds made minutes
    apart look identical without the stamp - this has already cost several
    test rounds.

Also worth knowing before you start:
  - F7 asks TWICE if you have local work to lose. That is deliberate.
  - Component settings apply when you CLOSE the properties panel, not while it
    is open. A couple of seconds' delay there is by design.

----------------------------------------------------------------------
0. PREP  (both machines)
----------------------------------------------------------------------
[ ] Both: run install.bat, then launch Stormworks. No injector, nothing to run
    per session.
[ ] Both: watch the loading screen - the mod's startup panel should appear and
    tick through its steps. If it does not, stop and send the log.
[ ] Both: SAME base game version, SAME workshop part mods (if any).
[ ] Both: CUSTOM gamemode, at the SAME workbench type. Bench sizes differ and
    the mod will deliberately block sync if they do not match.
[ ] Agree who is A and who is B, and keep it that way in your notes.

----------------------------------------------------------------------
1. PAIRING
----------------------------------------------------------------------
[ ] Neither player types a SteamID anywhere.
[ ] Both: F6 - the panel should show a partner within a few seconds of both
    being in-game.
    Expect in the log:  'auto-connect: adopted peer'  /  '*** LINK LIVE ***'
[ ] If it never pairs: check you are Steam FRIENDS, and that Steam privacy is
    not hiding game details - that blocks the discovery beacon silently.

----------------------------------------------------------------------
2. BENCH IDENTITY
----------------------------------------------------------------------
[ ] Both at the SAME bench type            -> sync allowed.
[ ] Deliberately try DIFFERENT bench types -> sync REFUSED, with an on-screen
    message saying so. That is the guard working, not a failure.
[ ] Return to matching benches for everything below.

----------------------------------------------------------------------
3. FIRST BLOCK EACH WAY   *** DO THIS BEFORE ANY OTHER BUILDING ***
----------------------------------------------------------------------
The single most important untested thing. Neither of you has placed anything.
[ ] A places ONE block  -> appears on B, in the right place, immediately.
[ ] B places ONE block  -> appears on A, in the right place, immediately.
If either is lost or lands wrong, note it and carry on - that result is the
point of the whole session.

----------------------------------------------------------------------
4. CORE EDITS   (do on A, verify on B; then swap)
----------------------------------------------------------------------
[ ] SINGLE PLACE   one block                -> appears.
[ ] DRAG / AREA    a line, then a big fill  -> all appear, none missing.
[ ] SHAPES         wedges / pyramids        -> correct shape, no sawtooth.
[ ] ROTATION       a rotated block          -> same orientation.
[ ] COLOUR         a coloured block         -> same colour.
[ ] PAINT          repaint a block, then ONE FACE of it -> both carry.
[ ] DELETE         single delete, then drag-erase a row -> all removed.
[ ] SYMMETRY       place with symmetry on   -> both sides appear.
[ ] WIRES          connect electric, connect logic, then DISCONNECT one.
[ ] BATTERY        change a battery's charge -> carries over.

----------------------------------------------------------------------
5. MOVE TOOL
----------------------------------------------------------------------
[ ] A slides the whole craft -> B sees it move.
    Never tested cross-machine. If it does not work, note it and carry on.

----------------------------------------------------------------------
6. COMPONENT SETTINGS   (new - works solo, never tried with a partner)
----------------------------------------------------------------------
[ ] A renames a dial, closes the panel -> B's dial takes the name.
[ ] A changes a dial's min/max         -> B matches.
[ ] A edits a microcontroller's internals, closes the editor -> B matches.
    This is the big one. MC blobs are large and this is their first real
    outing; if anything here fails, expect it to be this.
[ ] Note roughly how long each takes to appear.

----------------------------------------------------------------------
7. LEAVING, JOINING, PRESENCE
----------------------------------------------------------------------
[ ] E vs Q: opening the bench with E is CO-OP, Q is SOLO. Confirm the prompt
    text matches what you are about to do, on both machines.
[ ] B leaves the bench while A keeps building -> A's sync pauses, no errors.
[ ] B returns -> B catches up automatically, without pressing anything.
[ ] B leaves and re-enters as JOIN PARTNER -> B pulls A's whole craft, with a
    progress banner. A failure should show a red reason, never fail silently.

----------------------------------------------------------------------
8. F7 WHOLE-CRAFT PULL   *** move the craft first - see rule 2 ***
----------------------------------------------------------------------
[ ] A moves their craft to one spot; B moves theirs to a DIFFERENT spot.
[ ] B presses F7 (twice, to confirm) -> A's craft arrives on B.
       -> Does it land in the RIGHT PLACE?   <- the open bug we are hunting
       -> Are wires, microcontrollers and settings intact?
       -> Any yellow warning icons left on screen afterwards?
[ ] Then the other direction: A presses F7 -> B's craft arrives on A.
[ ] Whatever happens, grab the log line starting '[snap] poff' from BOTH
    machines. That line is the answer to the position question.

----------------------------------------------------------------------
9. CAPTURE THE GIF   *** do not end the session without this ***
----------------------------------------------------------------------
[ ] Record 5-10 seconds of both screens: one player building, the other screen
    filling in live. Split-screen, or two windows side by side.
It is the single best answer to "is this real", it costs nothing while two
machines are already running, and it cannot be recreated afterwards.

----------------------------------------------------------------------
AFTERWARDS
----------------------------------------------------------------------
[ ] Send coopworkbench-log.txt AND wsdraw-log.txt from BOTH machines, plus
    coopworkbench-CRASH.txt if one appeared. Remove the 17-digit SteamID64s.
[ ] Note what each of you SAW, separately. "It didn't sync" is usually two
    different stories on the two screens, and the difference is the clue.
[ ] You can read the log in-game with F8 (PgUp/PgDn scroll, F2 to filter to
    errors) - usually faster than finding the file.
